# ADR-0005: Voice gateway design

Date: 2026-07-17 · Status: Accepted

## Context

The gateway owns the live call: Twilio Media Streams WebSocket in, streaming STT → LLM → TTS
pipeline out, under the p50 ≤ 1.2s voice-to-voice budget (docs/latency-budget.md). It is the
only stateful service (ADR-0002).

## Decisions

### 1. One audio format end-to-end: μ-law 8kHz

Twilio Media Streams speaks base64 μ-law 8k. Deepgram ingests `encoding=mulaw&sample_rate=8000`
natively, and ElevenLabs emits `ulaw_8000` directly. Zero transcoding on the hot path — the
gateway moves base64 payloads. (A PCM16 μ-law codec still lives in `telephony/audio.ts` for
tests and future providers.)

### 2. Providers behind minimal interfaces, raw WebSockets for speech

`SttStream`, `TtsSession`, `LlmTurnRunner` interfaces with one production implementation each:

- **Deepgram** (nova-3, `language=multi` for Hindi/English code-switching) over a raw WS —
  interim results stream for the dashboard, `endpointing` + `UtteranceEnd` mark end-of-speech,
  `SpeechStarted` VAD events drive barge-in. KeepAlive every 8s.
- **ElevenLabs** `stream-input` WS (flash model, `auto_mode`) — one socket per agent turn,
  opened concurrently with the LLM request so its connect cost hides inside LLM TTFT.
- **Anthropic** via the official SDK: streaming Messages with the tool definitions generated by
  `@vaanidesk/agent`; the system prompt carries `cache_control` so per-turn input cost and TTFT
  drop after turn one. Max 3 tool rounds per turn, each guarded by the budget reducer.

Interfaces exist for failover later (Sarvam STT/TTS are config swaps, documented not built).

### 3. Per-call state machine, pure transitions

States: `connecting → greeting → listening → thinking → speaking → transferring/ending → done`.
Transitions live in `call/state.ts` as a pure function (unit-tested); `CallSession` executes
side effects. Illegal transitions throw in dev and are logged+ignored in prod — a race between
a late TTS chunk and a hangup must never crash the process (other calls share it).

### 4. Barge-in: Deepgram VAD + Twilio `clear`

While `speaking`, a `SpeechStarted`/interim-with-content event: aborts the LLM stream
(AbortController) and TTS socket, sends Twilio `clear` to flush its jitter buffer, and
transitions to `listening`. Target ≤100ms from detection to silence. The interrupted agent
utterance is recorded with what was actually spoken (up to the last played sentence mark).

### 5. Transfer goes through the api

`transfer_to_owner` calls `POST /v1/internal/calls/:id/transfer`; the **api** redirects the
live call via Twilio's REST API to `<Dial>ownerPhone</Dial>` TwiML. The gateway never holds
telephony REST credentials (ADR-0002 boundary). If the api can't transfer (no owner phone, no
creds), the gateway apologises and ends gracefully.

### 6. Durability: fire-and-forget with retry, completion is authoritative

Turn records post to the api on a small in-session retry queue (never blocking the audio path).
Call completion (outcome, latency rollup, cost, token usage) is sent once at end with retries;
if the gateway dies first, the api's status webhook reconciles (ADR-0004). Live dashboard
events publish direct to Redis pub/sub — lossy by design, the DB is the record.

### 7. Graceful drain

SIGTERM: stop accepting WS upgrades (503 on upgrade), let active calls finish up to
`DRAIN_TIMEOUT_MS` (default 5 min), then complete stragglers as `failed` and exit. Deploys
never drop a live conversation.

## Consequences

- The pure modules (chunker, state machine, media protocol codec, latency timer, μ-law codec)
  carry the unit-test load; provider clients are thin and replaceable.
- Latency stamps are taken at every stage boundary in `call/latency.ts` and shipped on every
  turn — the latency budget is measured, not aspirational.
